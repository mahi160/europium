# Domain docs

This repository uses single-context domain documentation.

## Before exploring

Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these do not exist, proceed silently. Create domain documentation
only when terminology or decisions are resolved through domain modeling.

## Vocabulary

Use glossary terms in tickets, code, tests, and documentation.
If a needed concept is missing, reconsider the terminology or note
the gap for domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly before proposing
a contradictory change.
