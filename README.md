# Office Service

A self-hosted office refreshment application with Bengali and English interfaces. Employees place personal orders, support staff claim and fulfill whole orders, and administrators manage people, refreshments and exceptions.

## Install

Office Service runs in an Alpine Linux LXC container (for example a Proxmox CT) as a single Bun binary behind Caddy. Follow [the LXC install](docs/deployment.md#install) to set it up once. Afterwards, pushing to the `deploy` branch builds a release that the server installs automatically within 5 minutes; see [auto-update](docs/deployment.md#deploying-and-auto-update).

Install the office certificate on client devices before entering credentials: see [device trust](docs/deployment.md#connect-devices-install-the-office-certificate). Then open the displayed HTTPS address and use `SETUP_TOKEN` from the protected `/etc/conf.d/office-api` to create the first administrator. Never share that file.

## Development

Use Node 24, pnpm 12.14.0 and Bun 1.4.5 (the API runs on Bun; the web frontend builds with Node):

```sh
pnpm install --frozen-lockfile
```

Create a protected, git-ignored development configuration once. This command preserves an existing file and writes random secrets directly to the file without displaying them:

```sh
if [ ! -e .env.development ]; then
  (
    set -euC
    umask 077
    auth_secret=$(openssl rand -hex 32)
    setup_token=$(openssl rand -hex 32)
    printf 'APP_ORIGIN=http://localhost:5173\nDATABASE_PATH=./data/office.sqlite\nAUTH_SECRET=%s\nSETUP_TOKEN=%s\n' \
      "$auth_secret" "$setup_token" > .env.development
  )
fi
```

Open `.env.development` privately in your editor when the setup screen asks for `SETUP_TOKEN`. Do not post the file or token, put it in a URL, or bundle it into frontend code.

Start the backend from a shell that loads this trusted operator-owned file:

```sh
set -a
. ./.env.development
set +a
pnpm dev:api
```

In another terminal:

```sh
pnpm --filter @office-service/web dev
```

Open the configured origin and complete the one-time administrator setup. There are no seeded credentials or public registration. Employees and support staff sign in with a username and exactly four ASCII digits as their PIN, including leading zeros. Administrators keep 12–128-character passwords. Administrator-created accounts must change their temporary PIN or password. Administrators can also order refreshments personally.

New employees and support staff default to the temporary PIN `0000` unless an administrator overrides it when adding them. They must choose a different PIN at first sign-in. A shared default is predictable: anyone who knows a new username can sign in before its owner changes the PIN. Issue a unique temporary PIN when that risk is unacceptable. Administrators never receive a default password.

Four-digit PINs prioritize convenience over password strength. Login and current-credential verification share a persistent five-attempt limit per account per 15-minute window; successful verification or an administrator reset clears that account's attempt counter. Keep HTTPS and the office LAN restriction enabled. PINs are server-secret-peppered before password hashing; preserve `AUTH_SECRET` in protected backups.

The PIN migration signs existing employees/staff out; their old passwords are no longer accepted. An administrator must issue a temporary PIN through People. Moving an account between administrator and non-administrator roles revokes its sessions and requires an administrator to reset its credential for the new role. Staff/employee role changes keep the PIN.

`PORT` optionally changes the API's listening port; set frontend tooling's `API_ORIGIN` to the matching upstream. `APP_ORIGIN` always means the browser's exact origin. The PWA service worker is generated by the production build, not the normal development server.

## Checks

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm --filter @office-service/web build
pnpm exec playwright install chromium
pnpm exec playwright test
pnpm exec playwright test --config playwright.pwa.config.ts
pnpm exec playwright test --config playwright.ui.config.ts
```

The browser suites create isolated temporary databases. They use ports 3013/5183, 3014/5184 and 3025/5195 and refuse to reuse unrelated servers. The UI suite covers role-first navigation, dialog keyboard focus, menu/person editing, contextual order instructions, staff handoffs and safe order retries at desktop, tablet and phone widths. Current results and outstanding failures are recorded in [verification.md](docs/verification.md); not all acceptance checks are complete.

Vite+ provides tasks, Vitest, lint and formatting. `pnpm fmt --check` checks formatting; `pnpm fmt` rewrites files.
